# Closeout of a sub-project or long-running branch

Open when a spec-and-plan effort is about to merge.

Specs and plans are working documents. Before merging: fold durable facts into the requirements
documents and `.agents/AGENTS.md`, leftovers into todo and questions, keep only open work, then
delete the spec and plan. Code and docs never cite spec sections or plan tasks; do not keep a
finished spec "for reference".

Check coverage: list each durable fact of the spec as present, partial or missing in the records,
with file and line. Verify partial and missing ones against the spec and the code before proposing
wording. Accepted costs and rejected alternatives are the facts most often missing.

Write amended requirements as current behaviour, not history ("changed from X to Y").
